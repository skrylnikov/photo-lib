## Context

Текущий `share-web` уже содержит workspace админки, локальное состояние формы создания альбома, очередь direct-to-storage загрузок, автоматическое polling-синхронизирование и HTML5 drag-and-drop для состава. `share-api` уже сохраняет `targetAlbumId`, автоматически создаёт `AlbumMedia` после обработки и нормализует `position`; защищённый `/media/:mediaId/:format/:width` подходит для превью готовых медиа. См. [proposal.md](proposal.md) и delta-spec для пользовательского контракта.

## Goals / Non-Goals

**Goals:**

- Упростить workspace без изменения существующего API workflow загрузки и обработки.
- Сделать создание альбома явным, но быстрым: открыть модалку, создать черновик, выбрать его и сразу использовать как цель загрузки.
- Отображать готовые неназначенные медиа визуальными карточками и поддержать предсказуемую перестановку состава.
- Не показывать пользователю действие загрузки там, где оно запрещено состоянием альбома.
- Сохранить keyboard/touch fallback, dirty-state, безопасные ошибки и автоматическое появление обработанных фото в составе.

**Non-Goals:**

- Новый endpoint, новая модель batch-загрузки, Prisma migration или внешний drag-and-drop dependency.
- Изменение серверных правил публикации, порядка обработки, форматов derivatives или публичной выдачи медиа.
- Совместное редактирование и разрешение редактировать опубликованный альбом.

## Decisions

### 1. Использовать существующую Mantine Modal и локальное состояние формы

Sidebar будет содержать только кнопку создания. Поля `newTitle` и `newSlug` останутся локальным состоянием страницы и будут показаны внутри `Modal`; submit вызовет существующую `createAlbum`, затем обновит данные, установит id созданного альбома как выбранный и закроет модалку. При ошибке модалка останется открытой, чтобы исправить поля, а безопасное сообщение отобразится в общем состоянии операции.

Альтернатива — отдельная страница или inline accordion — отклоняется: для двух обязательных полей это создаёт лишнюю навигацию или всё равно оставляет форму постоянно видимой.

### 2. Скрывать upload card по состоянию выбранного альбома

Рендер секции «Мультизагрузка» будет условным по `selectedAlbum.published`. Для опубликованного альбома не показываются dropzone, selector назначения, input и очередь в этой секции. При выборе черновика секция появляется с выбранным черновиком как `targetAlbumId`. Существующие активные queue items не отменяются и не удаляются при смене альбома; их состояние остаётся доступным после возврата к соответствующему черновику, а серверная проверка по-прежнему защищает опубликованный альбом.

Альтернатива — оставить disabled-карточку — отклоняется, потому что она сохраняет визуальный шум и создаёт ощущение, что загрузка является действием опубликованного альбома.

### 3. Переиспользовать защищённые JPEG derivatives для готовых медиа

Секция готовых неназначенных медиа будет сеткой карточек, аналогичной составу альбома. Для `status === 'ready'` используется `/media/:id/jpeg/640`; имя, статус и кнопка добавления остаются видимыми. Доступность превью определяется уже существующим authenticated media route и наличием готового derivative; новый публичный путь не добавляется. Если изображение не загрузилось, карточка сохраняет имя и действие добавления, а UI показывает безопасный fallback вместо пустого места.

Локальные object URLs применяются только к ещё не обработанным файлам в upload queue и продолжают освобождаться при удалении/размонтировании.

### 4. Сделать drag-and-drop составом с серверным сохранением текущего порядка

Карточка состава будет draggable только для неопубликованного альбома. На `dragStart` запоминается id медиа, на карточках-целях отменяется default dragover и drop вычисляет новый индекс в текущем `membership`. Перемещение помечает состав dirty, а существующая `setAlbumMedia` получает список в визуальном порядке; сервер остаётся источником истины и вычисляет уникальные позиции.

Кнопки «выше/ниже» остаются рядом с карточкой. Они нужны для клавиатурной навигации и устройств, где native drag-and-drop неудобен; это также не требует дополнительной зависимости. После сохранения или перезагрузки порядок берётся из `listAlbums` с сортировкой по серверной `position`.

### 5. Сохранить автоматическое назначение как единственный путь для новых загрузок

Выбранный черновик продолжает передаваться в каждый `createUploadIntent`. После обработки job runner добавляет готовое медиа в этот альбом, а условный polling обновляет `albums`, `media`, queue и membership. UI не будет добавлять локальный placeholder в состав до готовности derivative и не будет требовать ручного нажатия «Добавить» для нового файла. Ручное добавление остаётся только для уже существующих готовых медиа без членства в альбоме.

## Risks / Trade-offs

- [Модалка может закрыться до завершения обновления списка] → закрывать её только после успешного создания и выбирать возвращённый id созданного альбома.
- [Старое queue-состояние может быть скрыто при выборе опубликованного альбома] → не удалять и не отменять очередь; повторное открытие черновика снова показывает её, а polling продолжает работать при активных серверных состояниях.
- [Браузер не может отобразить JPEG derivative] → оставить metadata карточки и безопасный placeholder, не раскрывать object key и не считать ошибку превью ошибкой назначения.
- [Drop может переставить карточку не в ожидаемое место] → обновлять локальный список только после валидных from/to индексов, сохранять кнопки направления и проверять повторное открытие после сохранения.
- [Существующий code path уже частично реализует drag-and-drop] → сначала покрыть/проверить нужные сценарии и изменить только UX-границы, не добавляя вторую модель порядка.
