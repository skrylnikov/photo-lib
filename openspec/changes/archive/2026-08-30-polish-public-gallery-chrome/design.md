## Context

См. `proposal.md` — Why. Vite использует `apps/share-web/src` как root: `index.html` содержит статический `Photo Lib` и закомментированный favicon, а React-приложение переключает `/`, `/album/<slug>` и `/admin` собственным `history.pushState` без отдельного router. `FilmGallery` уже имеет общий `action`-slot в заголовке бумажной подложки, но главная использует его только для `Open album`, а `AlbumPage` выводит `Back to gallery` отдельной строкой. Публичный home DTO возвращает только избранные фотографии и поэтому пока не знает полный размер альбома.

## Goals / Non-Goals

**Goals:**

- Добавить согласованную идентичность маршрутов без новой routing-, metadata- или icon-зависимости.
- Сделать переход в полный альбом и возврат одной семантической и визуальной системой.
- Сообщать полный размер альбома без загрузки или раскрытия всех его media на главной.
- Сохранить native link-поведение, keyboard focus и устойчивую мобильную геометрию.

**Non-Goals:**

- Переработка плёночных линий, paper backdrop, viewer, origin-linked transitions или состава альбома.
- Полная система локализации либо новый брендбук.
- Manifest, PWA, `apple-touch-icon`, новые шрифты или icon library.

## Decisions

### 1. Статическая основа metadata и минимальные маршрутные обновления

`index.html` получит `lang="ru"`, локальный SVG-favicon и безопасный fallback-title `dskr.photos`. React-страницы будут устанавливать `document.title` непосредственно при смене своего состояния: главная — `dskr.photos — фотоальбомы`, admin — `Библиотека — dskr.photos`, `AlbumPage` после ответа — название альбома либо «Альбом не найден». Это короче и надёжнее для существующего трёхмаршрутного приложения, чем metadata provider или полноценный router.

Альтернатива: единый title-map только в `App`. Она не выбрана, потому что `App` не владеет асинхронно загружаемым названием альбома и потребовала бы поднимать это состояние либо вводить новый контекст.

### 2. Favicon как самостоятельный локальный SVG

В root Vite будет добавлен небольшой SVG без текста и внешних ресурсов: тёмный кадр/полоса с крупными светлыми перфорациями на тёплом фоне. Геометрия проектируется для 16×16, а не переиспользует широкий `film-mask.svg`, который теряет смысл в квадратной вкладке. `index.html` будет ссылаться на asset так, чтобы Vite включил его в production build.

Альтернатива: буквенный monogram или растровый набор размеров. Не выбрана: шрифт в маленькой иконке нестабилен, а дополнительные PNG и manifest не нужны для обычного favicon.

### 3. Полный размер альбома считается на сервере без выдачи записей media

Home query получит фильтрованный relation count для назначенных media со статусом `ready` и хотя бы одним derivative. В DTO альбома добавится только `photoCount`; массив `photos` останется избранной подборкой. Это сохраняет текущую границу приватности и не передаёт лишние карточки ради одного числа.

Альтернатива: считать `photos.length` на клиенте. Не выбрана, потому что это число отражает только избранную подборку и делает подпись действия ложной.

### 4. Русские числительные форматируются через стандартный `Intl.PluralRules`

Существующий formatter количества кадров будет переведён на русские формы и переиспользован для обычного счётчика, варианта «избранный кадр» и текста `Все N кадров →`. Новая библиотека или таблица локализации не нужна; достаточно `Intl.PluralRules('ru')` и трёх форм слова.

### 5. Навигация остаётся настоящими ссылками и переиспользует `action`-slot

Главная передаст в `PublicGallery` ссылку `href="/album/<slug>"`, а `AlbumPage` — `href="/"` через тот же `action`-slot. Обычный primary-click можно перехватить существующим `navigate` для SPA-перехода, но modified-click, middle-click и копирование адреса MUST оставаться native. Отдельный универсальный Link-компонент не вводится: двух мест недостаточно для новой абстракции.

`FilmGallery` получит минимальный способ передать готовую подпись счётчика, чтобы главная могла сказать «M избранных кадров», а полная страница сохранила обычное «N кадров».

### 6. Action-стиль принадлежит общей галерее

Action-slot будет оформлен как тихая контурная кнопка в цветах paper backdrop с едиными hover и focus-visible состояниями и высотой не менее 44 CSS px. На desktop он остаётся напротив заголовка; при `max-width: 640px` заголовок и action складываются вертикально, чтобы длинное название не конкурировало со ссылкой. Отдельная строка над альбомом удаляется.

## Risks / Trade-offs

- [Фильтр полного count разойдётся с фильтром фотографий полной страницы] → использовать те же условия `ready` и наличия derivative и закрепить это focused API-проверкой.
- [Асинхронный album title кратко покажет fallback] → до завершения запроса оставлять нейтральный `dskr.photos`, затем атомарно установить итоговый title.
- [SPA click-handler сломает открытие в новой вкладке] → перехватывать только немодифицированный primary-click и вручную проверить Ctrl/Cmd-click и копирование URL.
- [Длинные названия снова столкнутся с action] → проверять desktop и viewport 390 px, перенос заголовка, область 44×44 px и отсутствие horizontal overflow.
- [SVG читается в большом preview, но теряется во вкладке] → проверять favicon в фактическом размере 16×16, а не только исходный SVG.

## Migration Plan

1. Добавить `photoCount` в обратносуместимый публичный home DTO и обновить клиентские типы через существующий tRPC inference.
2. Добавить metadata, favicon, русские formatter/labels и общую action-композицию.
3. Выполнить focused tests, lint, typecheck и production build обоих затронутых приложений; визуально проверить главную и альбом на desktop/mobile.
4. Развернуть обычным образом без database migration. Rollback — вернуть web/API commit; сохранённых данных и schema changes нет.
