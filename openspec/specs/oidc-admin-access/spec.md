# oidc-admin-access Specification

## Purpose

Защитить все административные операции библиотеки проверкой личности Pocket ID и отзывными server-side сессиями, сохранив преднамеренно анонимный доступ к публичной галерее.

## Requirements

### Requirement: Административный доступ требует разрешённой личности Pocket ID
Система SHALL требовать успешной OpenID Connect-аутентификации в Pocket ID до выдачи содержимого `/admin` или выполнения административной операции. Она MUST авторизовывать только настроенные subject владельцев или разрешённые группы.

#### Scenario: Разрешённый владелец открывает админку
- **WHEN** разрешённый пользователь Pocket ID завершает вход
- **THEN** он получает доступ к админке и её административным операциям

#### Scenario: Неразрешённый пользователь Pocket ID завершает вход
- **WHEN** личность Pocket ID, не имеющая права на библиотеку, завершает вход
- **THEN** система отказывает в доступе к админке и не создаёт административную сессию

### Requirement: OIDC-ответ проверяется до создания сессии
Система MUST проверять state, nonce, issuer, audience, подпись и срок действия ответа авторизации до признания личности аутентифицированной. Она MUST создавать непрозрачную server-side сессию и передавать её только в secure HTTP-only cookie.

#### Scenario: Получен недействительный callback
- **WHEN** callback содержит недействительный, просроченный или не совпадающий OIDC-ответ
- **THEN** система не создаёт сессию и возвращает безопасную ошибку аутентификации

### Requirement: Сессии истекают и завершаются выходом
Система SHALL завершать административные сессии по сроку действия и предоставлять logout, инвалидирующий server-side сессию. Запрос с просроченной, отсутствующей или отозванной сессией MUST считаться неаутентифицированным.

#### Scenario: Администратор выходит из системы
- **WHEN** администратор выполняет logout
- **THEN** последующие административные запросы с прежней cookie отклоняются

### Requirement: Публичный сайт не рекламирует доступ к админке
Публичная галерея SHALL не содержать навигации или призыва к действию, ведущего на `/admin`. Отсутствие ссылки MUST NOT заменять server-side авторизацию.

#### Scenario: Анонимный посетитель просматривает публичную галерею
- **WHEN** анонимный посетитель открывает публичные страницы
- **THEN** ссылка на админку не рендерится, а все административные API остаются защищёнными

### Requirement: Development auth bypass требует явного локального opt-in

Система MUST NOT выдавать административную сессию без cookie только на основании `NODE_ENV=development`. Development auth bypass SHALL включаться отдельной явной настройкой, SHALL действовать только в development runtime и MUST оставаться выключенным по умолчанию.

#### Scenario: Development runtime запущен без bypass
- **WHEN** приложение работает с `NODE_ENV=development`, но отдельная настройка bypass отсутствует
- **THEN** запрос без действительной session cookie остаётся неаутентифицированным и не получает доступ к admin procedures

#### Scenario: Локальный разработчик явно включает bypass
- **WHEN** development runtime запущен с документированной opt-in настройкой bypass
- **THEN** локальный запрос без session cookie получает development principal для тестирования admin workflow

#### Scenario: Bypass ошибочно задан в production
- **WHEN** production runtime получает настройку development bypass
- **THEN** bypass игнорируется или startup завершается безопасной ошибкой, а запрос без действительной session cookie остаётся неаутентифицированным
